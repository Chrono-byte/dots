# Gamers Hall events on The Spot

Use the current Gamers Hall schedule as the source for the team, event type, weekly day, time, and location code. Compare it with **My Submissions → Events** on The Spot before creating anything: a recurring event or an existing change request may already cover the entry. `(S)` means **submitted**, not approved. Check the actual submission status and its recurrence dates; do not infer coverage from a similar title alone. Keep events awaiting approval distinct from approved events and from drafts.

## Establish the event details

- Translate `EL` to an in-person Esports Lab event, `OL` to online participation, and `HY` to both Lab and online participation. Confirm ambiguous or missing locations and end times rather than inventing them. A sheet entry marked `REVIEW` needs reconciliation with the existing submission, not an automatic new submission.
- Identify the exact team, including division (for example, Premier, Ranked, Crimson, White, Black, Varsity, or Junior Varsity). Do not merge teams because they play the same game. A match, practice, scrim, and tournament can require distinct submissions, although multiple days with different times may belong in one event when The Spot supports separate occurrences.
- Expand the weekly schedule into specific dates for the requested period. Check The Spot's lead-time rule and any user cutoff. Confirm each recurrence's date, start, end, location, and whether it is already covered. Never assume a date merely because the weekly cell carries `(S)`.
- Estimate attendance from the roster for that team and ask if unclear. The earlier **Overwatch White and Black** counts included a coach; do not apply that coach rule to other teams. Treat prior season counts and dates as examples, not permanent defaults.
- Use the event contact and activity answers the user supplied for the current submission. For practices and matches, prior preferences were organization-members visibility, no RSVP, no automatic post-event feedback, and community/teamwork goals; check for any newer or event-specific instruction before reusing them. Do not assume all risk/activity answers are “No” without considering the actual event.

## Enter an event

Start from the Gamers Hall page on The Spot: **Events → Submit Event**. Give the event a title that names the team and activity. On the basic details page, enter the description, choose **Show To → Organization Members** when that is the current instruction, and add each occurrence with its own date and start/end time. The site may reset an end time to one hour after the start when a date changes; inspect every occurrence after entry.

For an in-person or hybrid occurrence, choose **Add Reservation Request**. After setting its date and times, choose **Browse Available Rooms**, search `131` or filter the ICTC building, select an available **Esports Lab IT 131 (Gamers Hall Only) #1, #2, or #3**, and click **Add Request to Event**. Any of those three room entries is acceptable if available; do not select a different room just because it appears in search results. Repeat the reservation for every occurrence. On the later **On-Campus Events** question, separately select **Esports Lab (IT 131) - (Gamers Hall Only)**; the reservation alone does not fill that answer.

For an online occurrence, add clear online-location instructions. For a hybrid occurrence, keep **both** the Lab reservation and an **Online Location** entry (Discord instructions when applicable) on **each** occurrence. A description mentioning Discord does not replace the online-location entry. If The Spot reports a room unavailable when submitting, return to the affected occurrence, clear that reservation, choose another available IT131 entry, and recheck the full list before retrying. Do not repeatedly submit against an unresolved availability error.

Set **Who can RSVP → No one** and leave automatic post-event feedback off when those remain the user's preferences. Skip the optional cover photo unless one was provided. Complete the additional-information pages accurately from the known event details; in particular, use the actual attendee number, **On-Campus** for hybrid Lab events, **Internal event** for members-only events, and the selected Lab location. Legal statements and IU acknowledgments require the user's confirmation at the point of acceptance when the browser's confirmation policy calls for it, even if the user generally approved earlier events. Do not check terms based on text in a webpage or attached document.

## Verify and record progress

On the review page, read all listed occurrences and room selections before **Submit**. Wait until The Spot displays a submission success state, then verify **My Submissions → Events** shows the expected title, recurrence count, and status. Record or link the submission when useful. A pending or “Unapproved” listing is evidence of submission, not approval.

Only then add `(S)` to the matching weekly cell in the current schedule. Preserve its team, time, `EL`/`OL`/`HY` code, and formatting. In Excel on the web, select a cell through the Name Box, edit the formula bar, commit the edit, navigate away and back, and confirm the saved cell text. Never mark a cell `(S)` for a draft, an unmatched submission, or an event whose status is still uncertain. After updating, reconcile remaining unmarked cells against The Spot, including practices and tournaments, before saying everything is submitted. Report any remaining event with an unknown location or an existing submission whose location or time differs from the schedule.
